เปิดระบบจริงด้วย Firebase ของคุณ

หน้าเว็บบน GitHub พร้อมใช้งาน ฐานข้อมูลธุรกิจยังว่างและยังไม่ได้เชื่อมบริการ ไม่มีรหัสผ่านเริ่มต้น

  1. เข้า Firebase Console แล้วสร้าง project ใหม่สำหรับสันป่าตอง
  2. เพิ่ม Web app ใน Project settings คัดลอก Firebase config เก็บไว้
  3. ไป Authentication → Sign-in method เปิด Email/Password
  4. ไป Authentication → Users → Add user สร้างบัญชีแอดมินด้วยอีเมลและรหัสผ่านของคุณ จากนั้นคัดลอก UID
  5. ไป Realtime Database → Create database เลือกตำแหน่งที่หน่วยงานต้องการ เริ่มด้วย Locked mode และคัดลอก Database URL
  6. ที่แท็บ Rules วางเนื้อหาจาก database.rules.json แล้ว Publish
  7. ที่แท็บ Data เพิ่มโหนด admins ใต้ root และเพิ่ม child ชื่อเป็น UID ของแอดมิน ค่าเป็นชนิด boolean true ห้ามใช้ string "true"
  8. กลับหน้าเว็บ กรอก Firebase config เป็น JSON ให้มี databaseURL ด้วย แล้วเชื่อมต่อ
  9. ล็อกอินแอดมิน ตั้งชื่อหน่วยงาน เพิ่มทะเบียน อุปกรณ์ และรับยอดยกมา

ตั้งค่า Allowed domains ใน Authentication ให้ตรงกับ hostname GitHub Pages ของคุณ หากเปิดใช้ provider ที่ต้องตรวจโดเมน ไม่มีการเปิดอ่าน/เขียนแบบสาธารณะใน Rules ที่ให้มา

ตัวอย่าง config ที่ต้องกรอก

{
 "apiKey": "คัดลอกจาก Firebase",
 "authDomain": "project-id.firebaseapp.com",
 "databaseURL": "https://ชื่อฐานข้อมูล.firebasedatabase.app",
 "projectId": "project-id",
 "appId": "คัดลอกจาก Firebase"
}

แทนค่าตัวอย่างทุกช่องด้วยค่าของคุณ apiKey ใน Web config เป็นค่าระบุ project ส่วนรหัสผ่านแอดมินและ service account key ต้องไม่อยู่ในไฟล์เว็บ

การกรอกที่หน้าเว็บจำเฉพาะเครื่องนี้ หากให้ทุกเครื่องพร้อมใช้งาน ให้แก้ config.js ใน GitHub แทน null ด้วย config object แล้ว commit ค่า Web config เท่านั้น

เมื่อเปลี่ยน config ส่วนกลาง ให้ผู้ใช้ออกจากระบบและเปิดใหม่ การจำ session ใช้เฉพาะรอบเบราว์เซอร์ ไม่จำรหัสผ่านในเว็บ

รุ่นเริ่มต้นทำอะไรได้

ล็อกอินแอดมิน • ทะเบียน/เปิดปิดใช้งาน • นำเข้า CSV แบบตรวจรายการก่อนยืนยัน • เพิ่ม SKU • รับเข้า • เบิกหลายรายการ • กระทบยอด • ปรับยอดพร้อมเหตุผล • ประวัติ • ส่งออก CSV • พิมพ์เป็น PDF • สำรอง JSON

ยังไม่มีหน้า QR เบิกสาธารณะ การอัปโหลดภาพโดยตรง หลายบทบาท การยกเลิกเอกสาร และนำเข้า backup ผ่านหน้าเว็บ หลักฐานรุ่นนี้เป็นลิงก์ HTTPS โดยคุณต้องตั้งสิทธิ์ไฟล์ในบริการเก็บไฟล์เอง

ทุกบัญชีที่อยู่ใน admins เป็นแอดมินคลังเดียวกัน สามารถอ่านและแก้ข้อมูลหน่วยงานได้ Rules ป้องกันคนไม่มีสิทธิ์ แต่ไม่ได้ทำให้แอดมินเป็นผู้ใช้ที่แก้ข้อมูลผ่าน API ไม่ได้ ควรเก็บ backup และจำกัดบัญชีแอดมินให้ผู้รับผิดชอบจริง

ธุรกรรมรุ่นแรกทำที่โหนด office ทั้งก้อน เหมาะเริ่มคลังเดียว ข้อมูลมากขึ้นควรย้ายธุรกรรมไป backend แยกเอกสารและเพิ่มระบบตรวจสอบถาวร
